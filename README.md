Каркас backend-приложения на FastAPI, построенный по принципу contract-first. Он предназначен для публичного справочника, тренажёра ЕГЭ, сохранения прогресса зарегистрированных пользователей и управления учебными материалами администраторами.

В режиме разработки код входа выводится в терминал Uvicorn:

Реализованы следующие endpoints:

```text

POST   /api/v1/auth/email/verify-code
POST   /api/v1/auth/refresh
POST   /api/v1/auth/logout
GET    /api/v1/me
```

## Тесты и попытки

```text
GET  /api/v1/tests
GET  /api/v1/tests/{testId}
POST /api/v1/attempts
GET  /api/v1/attempts/{attemptId}
POST /api/v1/attempts/{attemptId}/answers
POST /api/v1/attempts/{attemptId}/complete
```

Поддерживаются вопросы `single_choice`, `multiple_choice`, `text`, `matching`
и `ordering`. Правильный ответ не передаётся клиенту до отправки ответа ученика.
Анонимная попытка защищена токеном `X-Anonymous-Session`. У авторизованного ученика
результат записывается в статистику, а неправильные ответы — в очередь повторения.

Для локальной проверки можно один раз создать демонстрационный опубликованный тест:

```powershell
.\.venv\Scripts\python.exe -m app.scripts.seed_demo_test `
  --admin-email admin@example.com
```

## Управление вопросами и тестами

Все административные операции требуют Bearer-токен пользователя с ролью
`admin`. Обычный ученик получит ответ `403`, а анонимный пользователь — `401`.

```text
GET   /api/v1/admin/questions
POST  /api/v1/admin/questions
GET   /api/v1/admin/questions/{questionId}
PATCH /api/v1/admin/questions/{questionId}
POST  /api/v1/admin/questions/{questionId}/publish
POST  /api/v1/admin/questions/{questionId}/archive

GET   /api/v1/admin/tests
POST  /api/v1/admin/tests
GET   /api/v1/admin/tests/{testId}
PATCH /api/v1/admin/tests/{testId}
POST  /api/v1/admin/tests/{testId}/publish
POST  /api/v1/admin/tests/{testId}/archive
```

Новый вопрос и новый тест создаются как черновики. Каждое изменение вопроса
создаёт новую неизменяемую версию, поэтому старые попытки учеников не ломаются.
Перед сохранением вопроса проверяются текст, типизированный правильный ответ и
отсутствие такого же вопроса в выбранном тесте. Панель показывает понятные
предупреждения: «Нет текста вопроса», «Нет ответа» или «Такой вопрос уже существует».
Перед изменением или публикацией нужно передать актуальный заголовок `ETag` в
заголовке `If-Match`. Для операций создания, публикации и архивации также нужен
уникальный UUID в заголовке `Idempotency-Key`.

Сейчас публикуются фиксированные тесты. Черновик генерируемого теста создать
можно, но его публикация будет доступна после реализации генератора подборок.

Код входа в локальном режиме появляется в терминале Uvicorn. Токен хранится
только в текущей вкладке браузера и удаляется после выхода или закрытия вкладки.

Импортированные SQLite-файлы не остаются четырьмя рабочими базами приложения:
они загружаются в единую PostgreSQL-схему. В панели каждый источник представлен
самостоятельным справочником и никогда не смешивается с остальными в одном списке.
Связь с исходной базой хранится в `app.source_mappings`, а материалы редактируются
в `app.content_items` и типизированных таблицах `history_dates`, `terms`, `plans`.

## Локальный запуск

1. Скопируйте `backend/.env.example` в `backend/.env`.
2. Замените `EGE_JWT_SECRET` на криптографически стойкое случайное значение длиной не менее 32 символов.
3. Выполните из корня проекта:

   ```bash
   docker compose up --build
   ```

4. Откройте `http://localhost:8000/docs`.

Контейнер API дождётся запуска PostgreSQL, выполнит `alembic upgrade head`, а затем запустит Uvicorn.

## Импорт существующих SQLite-баз

Поместите в одну папку четыре файла, названия которых начинаются с:

```text
history_dates
history_terms
society_obsh
society_plans
```

Сначала выполните безопасную проверку без изменения PostgreSQL:

```powershell
.\.venv\Scripts\python.exe -m app.scripts.import_sqlite `
  --source-dir ..\data\sqlite `
  --dry-run
```

Если все четыре источника получили статус `OK`, запустите импорт:

```powershell
.\.venv\Scripts\python.exe -m app.scripts.import_sqlite `
  --source-dir ..\data\sqlite `
  --apply `
  --admin-email admin@example.com
```

Повторный запуск безопасен: неизменённые записи пропускаются, изменённые обновляются, а новые добавляются. Каждый фактический импорт записывается в `app.import_runs`, соответствия исходных записей сохраняются в `app.source_mappings`.
